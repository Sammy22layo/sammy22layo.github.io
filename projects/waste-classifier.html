Case study

Sorting waste from a phone camera

An image classifier that names a piece of waste — cardboard, glass, metal, paper, plastic or trash — from a single photo, deployed so anyone can open it and point their phone at a bin. The interesting part isn't the model that worked; it's the one that didn't.

The problem

Recycling only works if waste is separated at the source, and most people separating it are guessing — is a greasy pizza box cardboard or trash? Is this cup glass or plastic? A phone can settle it: point the camera, get the material. That's the tool this project builds — and ships, so it isn't a notebook nobody can run.

The data

The public Garbage Classification image set — 2,527 photos across six categories, split 80/20 into 2,022 for training and 505 held back for validation.

  • Six classes: cardboard, glass, metal, paper, plastic, trash.
  • Small, by deep-learning standards. 2,500 images is a few hundred per class — and that single fact shaped everything that followed.

First attempt: a model that memorised

I started where most people start — a convolutional network built from scratch, three convolution blocks into a classifier. Ten epochs in, the training accuracy looked superb: 96%. The validation accuracy — the only number that matters — sat at 64% and refused to move.

That gap has a name: overfitting. With only a few hundred images per class, a network with millions of free parameters doesn't learn what a glass bottle is — it memorises the specific bottles it was shown. On anything new, it guesses.

A high training score with a flat validation score isn't a model that works. It's a model that has memorised the answer sheet.

The fix: borrow features, stretch the data

Two changes, aimed straight at the small-data problem.

  • Transfer learning. Instead of learning vision from 2,500 photos, start from a network (MobileNetV2, then ResNet50) already trained on millions of ImageNet images, and retrain only the top for these six classes. The hard-won edges, textures and shapes come for free.
  • Data augmentation. Every epoch, each image is randomly rotated, shifted, zoomed, flipped and shifted in brightness — so the model never sees the exact same picture twice, and can't memorise its way out.

Validation accuracy climbed from 64% to about 75%, and the chasm between training and validation narrowed — the model was finally generalising rather than memorising. Both pretrained backbones landed in the same place, which says the ceiling here is the dataset, not the architecture.

An honest read

75% across six classes is a solid result for 2,500 images and random chance of 17% — but it isn't production-grade, and I'd rather say so than round it up.

  • The dataset is the ceiling. The clearest path past 75% is more and more varied images, not a fancier model — both backbones agreed on that.
  • "Trash" is a catch-all and the hardest class, since it's defined by not being the other five. A real deployment would need a confidence threshold and an "unsure" answer rather than a forced guess.
  • No separate test set. The 75% is validation accuracy; a true held-out test set would be the honest next step before trusting the number.

Deployed, not just trained

The best model is wrapped in a Streamlit app: upload a photo or take one on the spot, and it returns the predicted material with a confidence score. It runs in the browser — no setup, nothing to install — which is the whole point of building the tool rather than leaving it in a notebook.
